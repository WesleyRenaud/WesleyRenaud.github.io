Progress Review

Achieving My Goals

Below is a goal-by-goal reflection on progress against the learning goals I set for this Summer 2026 work term. The Job Skills page summarizes the resulting skill set more briefly.

1. Match existing codebase patterns

I believe that I have made solid progress towards this goal during this work term. When I was working on code changes this term, either as part of a new feature or as part of a bug fix, I focused on creating minimal solutions which do not disrupt the existing patterns in the codebase, and the existing app functionality. Instead of prioritizing getting a fix in, I focused on taking my time to evaluate all possible solutions to a problem, and then picking the cleanest one. This helped me find better, safer, and more efficient solutions to the problems I was faced with. I leveraged AI tools and documentation to evaluate existing structures and evaluate the risk and coupling of the changes I was proposing.

2. Improve code review and questioning

To achieve this goal, during this work term I made a point of consistently reviewing pull requests assigned to my team. When I performed these reviews I would carefully evaluate all parts of the code, and leave comments when I was unsure about a change, or thought that the code could be improved in some meaningful way. Going through this process regularly made me more conscious of the code I was writing, and how others could interpret my code. Sometimes I would make a change, reflect on it, and then make some adjustments based on potential issues I found.

3. Ask questions earlier about design decisions

Overall, I feel that I have become much better regarding this over my previous work term. I have not had any incidents where the work that I do deviates from the expectations in any meaningful way. The biggest aspect of this that I should continue to focus on pertains to bug fixes, and other issues alike. One of the trickier aspects of working on bugs at Brock has been identifying the root cause of an issue, which area of the code it lives in (does it belong to my team, or does this issue concern another team), and whether the fix is something small that can be done without any side effects and without much work, or whether it is more involved and requires design decisions. Some of the "bugs" that I have dealt with have not even been bugs—they may be expected behaviour, out-of-scope work which has never been implemented, or known issues. Balancing all of these possibilities is something that I have worked on through both of my work terms, and I plan to apply this new knowledge to future complex codebases which I work with.

4. Use AI more efficiently in development

During this past work term, I tried to incorporate AI into my day-to-day work. When I was working on features I would use AI to identify areas of the codebase that should be modified to implement the feature. I would ask it to create plans for implementing the code. After going through several rounds of revision of the code it creates, I am generally able to have something I am happy with. I regularly used AI to explore different possible implementations for a feature, and weigh their pros and cons. I would also use it to create tests. When fixing a bug I may get an agent to survey certain parts of the codebase which I believe could be the source of the issue. I would also use Microsoft Copilot to find feature specs, old conversations, meetings, and related material to try to evaluate the expected behaviour of a certain scenario, instead of having to wade through the documentation myself. I would also get it to create regression tests for the fixes that I make.

5. Time-box and escalate time-sensitive issues early

I made progress towards achieving this goal during this work term through achieving the other goals I created, for example using AI to improve efficiency, and by asking questions around design decisions when appropriate. The one or two times during this work term where I ran into time-sensitive issues—i.e. having to get a critical bug fix in—I communicated with my team and supervisor early in the process when I had any concerns about getting the fix in time, which allowed me to get the necessary support to get the issue resolved.
