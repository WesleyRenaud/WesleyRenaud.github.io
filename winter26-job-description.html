Role Overview

Job Description

My time at Brock Solutions has involved working on a mix of feature development, bug fixes, and regression testing. In most cases, I would spend several weeks working on a feature. A feature typically consists of several user stories, which could range from about a day's worth of work to closer to a full week. Completing a feature often required me to create multiple pull requests and move those changes through the review and approval process.

In between feature work, such as while waiting for specification reviews or feedback, I would work on bug fixes. A bug could take anywhere from an hour to several days to resolve, depending on the complexity of the issue. For the most part, the team focused primarily on feature work, though there were also times when the board had accumulated enough bugs that the team would spend a day focusing almost entirely on bug fixing before the next release.

What a typical work cycle looked like

Once a month, usually about a week before the monthly release, my team would complete a period of regression testing. The regression tests were selected based on the features that had been worked on and the parts of the system that had changed since the previous release. This testing period would often last several days. If any bugs were found during regression testing, their priority would be evaluated and the team would decide whether an immediate fix was necessary before release.

On a typical day, I would usually be working on one user story or one to two bug fixes, unless I was in the middle of transitioning between work items or the bugs I had picked up happened to have relatively quick solutions. This meant that my day-to-day work involved a balance of coding, debugging, communicating with teammates, and keeping my progress aligned with the release schedule.

A large part of my role involved feature work, debugging, and moving code through review.

Feature Work

Features were usually made up of several user stories and often involved coding, reviewing requirements, and creating multiple pull requests before the work was fully complete.

Bug Fixes

Bug fixes varied in size and urgency. Some were quick to resolve, while others required deeper investigation and more careful testing before they could be closed.

Regression Testing

Regression testing played an important role in the release cycle by helping the team verify recent changes and decide which issues needed immediate attention before deployment.
