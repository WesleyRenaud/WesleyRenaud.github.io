Role Overview

Job Description

In Summer 2026 I continued as a software developer on the SmartBag Reconciliation team at Brock Solutions. The day-to-day mix was still feature development, bug fixes, and regression testing, but my second term shifted toward handling that work more independently: investigating implementation approaches myself, ordering related tickets thoughtfully, and making stronger calls when a reported issue was a real defect versus as-designed behaviour, configuration, or a user problem.

Feature work often spanned several weeks and multiple user stories. Completing a feature usually meant several pull requests, reviews, and coordination with other teams when the work was split across areas of the product. Between feature stories, I picked up bugs—sometimes quick fixes, sometimes longer investigations—especially as release dates approached.

What a typical work cycle looked like

Once a month, usually about a week before the monthly release, the team completed a regression cycle. Tests were selected based on the features and modules touched since the previous release. High-priority regression bugs found in that window often had to be addressed before deployment, which made prioritization and early communication especially important.

On a typical day I worked on one user story or one to two bugs, balancing coding, debugging, code review, and keeping progress aligned with the release schedule. Larger items such as WSI Speedloader and British Airways grouping recovery were multi-team efforts, so part of the job was understanding where my slice ended and how it connected to work owned elsewhere.

Feature work, debugging, review, and release timing shaped most days on the team.

Feature Work

Features were usually made up of several user stories and often involved investigating existing patterns, reviewing requirements, and creating multiple pull requests before the work was complete.

Bug Fixes

Bug fixes varied in size and urgency. Some were quick to resolve, while others required deeper investigation, careful testing, and a clear judgment about whether a change was even the right response.

Regression Testing

Regression testing was a recurring part of the monthly release cycle, helping the team verify recent changes and decide which issues needed immediate attention before deployment.
