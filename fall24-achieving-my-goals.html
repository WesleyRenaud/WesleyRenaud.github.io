My first goal was to gain a better understanding of how much work I could complete in a given day which I aimed to complete by always having a list of the tasks that I had to complete, and picking out some for a given day to complete. I tried to break it down further by taking note of how long I thought each task would take me. As the term progressed I was able to more confidently wrap my head around how much time a given project or piece of a project would take to complete, and how much work I could get done towards my list in a given day. By the end of the term I was more able to stay ahead of the work I had and reach deadlines because I was more accurately able to create/suggest reasonable deadlines.

My second goal was to reduce the number of and the severity of the errors that I encountered when programming. My methodology to achieve this goal consisted of creating my code using incremental development and thorough and frequent testing. During the term I focused on developing programming habits that included using the tools in Visual Studio including the “build solution” feature and also the debugging tool with the step over, up, and down options. Anytime I made a change to the code base I re-built the solution, and whenever I added any functionality I made sure to step through the program to check for any errors. By the end of the term I was creating programs that encountered few major errors. Anytime there was an error I was able to find out where it came from, and in change this made me more efficient.

My third goal was to learn more CSS styles and attributes. During my first work I found that it took me longer than I would like to develop any visual interfaces. When I was developing these interfaces I often encountered situations where I wanted to make some slight change to the look of it, but I wasn’t sure how to edit the HTML and CSS to get the look I wanted and even when I did, it would mess up something else. During this term I focused on creating the GUIs I needed as much by myself as I could, and when I wasn’t sure how to do something, making note of whatever I did for future reference. During the term I learned more about CSS flex boxes, which helped me with creating interesting layouts for my GUIs, how to use margins and padding, how to organize items into rows and columns using “flex-direction”, and much more. The CSS knowledge I have gained during this work term has given me the ability to more easily and efficiently create my own visual interfaces with CSS and HTML.

My fourth goal for this work term was to learn the differences between the different project types available in Visual Studio. During my first work I ran into several instances where I had created a project using one type, but then later had to move the code over to a new project of another type. During this term I focused on gaining understanding of what each of these projects were used for and being able to select an appropriate project type for any new project. Using the projects I was working on, and the projects that I had already completed, I was able to grasp an understanding of what types of projects worked of what types of work (console vs web app, using web services vs not, etc.), and by the end of the term, when I believed it was beneficial, ported my projects to more suitable project types, and when creating a new project, I was consistently able to appropriately select the best type.

My fifth and final goal for the semester goes hand-in-hand with my first goal and was to become better at handling larger, more complex projects by breaking them down into many, smaller, more manageable tasks and focusing on those small tasks individually. Whenever I either was assigned a new project to work on, or given a lot of work to complete on some existing project, I created a list of all of the little things that I had to do for the project. I would then order the items of the list in the order in which I planned to complete them. I often put smaller, easier tasks towards the top so I could gain some sense of accomplishment and quickly cut down the length of the list. Anytime I was working on some sub-task and I encountered a good amount of difficulty with it, I’d move it down the list to re-visit it sometime later. When I came back to these tasks I was more often than not able to complete them easier. By the end of the term I developed a better approach for dealing with these larger projects, both in terms of my efficiency and my mental state when working on them.
