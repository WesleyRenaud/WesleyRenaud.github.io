JetBlue ADLFD Load Plan Message With Cargo

JetBlue uses ADLFD (Aero Data Load Flight Data) messages to define load plans for its flights. A load plan describes the expected weights, counts, volumes, and other values for the containers associated with a flight. As bags and cargo are loaded, the properties of those pieces must be compared against the load plan to make sure they do not exceed the expected limits. If loading a piece would exceed one of those values, the system generates an exception.

My task was to take the load plan message that Brock Solutions sends to JetBlue and modify it so that it also included cargo loaded onto the flight. Bags and cargo are stored differently in the system, and the existing load plan message only included baggage.

Implementation Process

Updating the existing load plan message involved several steps:

  • Fetch the cargo records from the database using the flight ID.
  • Extract the values needed for each cargo piece, such as weight, volume, and type.
  • Integrate the cargo pieces into the existing message structure alongside baggage.
  • Sort the bags and cargo by type and by the container they were loaded into.
  • Add a way to distinguish between baggage and cargo within the message.
  • Create a setting and factory-based switch so the system could use either the legacy generator or the new cargo-enabled generator.

That final rollout step was important because it allowed the new message to be tested more safely in the production environment while still giving the team the option to fall back to the legacy generator if any issues were found.
