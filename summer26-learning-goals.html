Work Term Objectives

Learning Goals

The goals I set for my second work term at Brock Solutions were as follows:

1. Match existing codebase patterns

Literacy - Technological Literacy

I want to focus on writing code which matches existing patterns and preferences within the codebase I am working in more closely.

Action Plan

In order to achieve this goal I will use AI and other tools to analyze and extract existing patterns within the code. I will focus on creating code that maintains the SRP / single responsibility principle and that cleanly separates responsibilities. I can also use previous pull requests and change logs to ensure my changes match current best practices and preferences.

Measure of Success

By creating code that matches existing patterns and preferences, it should fit into the existing codebase more easily, making adding additional features to it much simpler. It should also make tracking down certain functionalities or responsibilities within the code much easier.

2. Improve code review and questioning

Literacy - Technological Literacy

During my second work term at Brock I want to improve my abilities when it comes to reviewing code, and asking good questions about the code.

Action Plan

During this work term I plan to take more initiative when it comes to reviewing code through the PRs that get assigned to my team. When reviewing the code I will keep in mind whether it follows best practices and other practices within the codebase, and whether it is clear and legible. In cases where I feel that something in the changes is not intuitive in purpose, or unclear in any sense, I can leave a comment asking for clarity.

Measure of Success

By increasing my involvement in my team's assigned PRs, I will improve my ability to review and deliberately consider and evaluate code. It should also help me when it comes to writing my own code, in terms of picking up and adapting best styles and how different responsibilities are best broken up. When reviewing my own changes I can think about whether the code I have written aligns with patterns that I have seen elsewhere.

3. Ask questions earlier about design decisions

Critical & Creative Thinking - Problem Solving

During this term I want to become more proactive with asking questions and communicating with my team members regarding decisions to be made around the code I am writing and the projects I am working on.

Action Plan

When I am making initial / early decisions on how to implement a bug fix or feature, and I am unsure exactly on the best way to implement something, I want to ensure that I am reaching out to the appropriate person to seek advice on how to proceed.

Measure of Success

The idea with this goal is that when I am continuously writing code, the structure will be sound and allow for easier additions of new functionality. There were a couple of cases during my previous work term at Brock where I would need to make certain structural changes to a feature I was implementing, which would result in time lost due to work that did not actually resolve any functionality—changes which, if I had sought advice on earlier, would have never needed to be made.

4. Use AI more efficiently in development

Literacy - Technological Literacy

During this work term I want to use AI more efficiently when it comes to writing code, as well as when it comes to investigating and understanding the existing codebase.

Action Plan

During feature development I want to use AI tools to (a) understand existing coding patterns and best practices, and (b) use this knowledge to give drafts or proofs of concept for the changes. I anticipate that these pass-throughs will have issues with them, and likely not address the required changes in the exact way which I see them needed to be implemented, but the idea is that the AI will do a bulk of the grunt work early on. Reviews and careful consideration of the changes it makes will ensure that the quality of the code is not compromised by the AI. When it comes to fixing bugs, I can use AI for initial pass-throughs for determining expected behaviour (by analyzing things like tests), and for identifying parts of the codebase which could be worth investigating.

Measure of Success

The goal with using AI during development is to streamline the process, and reduce the time it takes for initial pass-throughs of code creation. The AI can provide me with outlines of possibilities for what the final code could look like, and once I have something which I believe to be structurally sound, I can jump right to the tweaking phase. When it comes to using AI to help with bugs, I believe that AI can help with what is generally the most time-consuming and least-rewarding part of fixing bugs, which is finding a good starting point for investigating where the error exists (i.e. finding a boundary of the API and checking what the data looks like).

5. Time-box and escalate time-sensitive issues early

Professional & Ethical Behaviour - Personal Organization / Time Management

During this work term I want to improve my tendency to time-box and ask questions early when dealing with time-sensitive issues.

Action Plan

When I am working on a time-sensitive issue or bug, I will time-box myself where I set out a certain amount of progress that I want to make within a certain amount of time (perhaps an hour or two) which aligns with what I believe I should accomplish in order to fix the issue on time. If I am not set to achieve this goal within the time box, I will reach out to seek guidance or clarity.

Measure of Success

By enforcing a time-boxing system like this when working on time-sensitive issues, I should ensure that I am always moving towards fixing these issues on time, which should result in reduced friction and stress within my team, and within my own work day.
